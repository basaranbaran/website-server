Giriş

Önemli Servisler & Notlar4 eğitimde geçen tüm Azure servislerinin tek sayfada özeti — ne işe yarar, hangi SDK, nasıl kimlik doğrulanır, en sık hata ne.

Bu sayfayı, 4 eğitimi hazırlarken kullandığım resmi Microsoft Learn sayfalarını ve kursların kendi GitHub alıştırma depolarını tekrar tarayıp, hangi servisin hangi eğitimde, ne amaçla, hangi SDK paketiyle geçtiğini tek yerde toplamak için hazırladım. Amaç, senin kendi ders notlarının yanına koyabileceğin, hızlı başvurulabilir bir "harita" oluşturmak.

Bir not

Mesajında kendi notlarından bahsettin ama bu sohbette bana ayrıca bir not dosyası ya da metni gelmedi — o yüzden bu sayfayı, 4 eğitimi hazırlarken derlediğim bilgilerin tamamını yeniden gözden geçirip güncel kaynaklarla doğrulayarak sıfırdan oluşturdum. Kendi notlarını da bana yapıştırırsan veya yüklersen, madde madde karşılaştırıp neyin doğru neyin güncel olmadığını birlikte kontrol edebiliriz.

Bu sayfa nasıl organize edildi?

  1. Genel kavramlar — 4 eğitimin de üzerine kurulduğu şemsiye terimler: Microsoft Foundry, Foundry Tools, Foundry Models, deployment/endpoint türleri.
  2. Kimlik doğrulama rehberi — hangi serviste API key, hangisinde Entra ID kullanılıyor, en çok karışan nokta bu.
  3. Eğitime göre servisler — her eğitimde geçen servisleri, o eğitimdeki sırasıyla listeler.
  4. Servisler arası bağlantılar — aynı servisin birden fazla eğitimde farklı yönlerden nasıl göründüğü (ör. Azure AI Search hem Eğitim 2'de hem Eğitim 4'te geçiyor).
  5. SDK özet tablosu — tüm pip install komutlarının tek listesi.

Endpoint karmaşası — bu kursların en sık yapılan hatası

4 eğitim boyunca üç farklı endpoint türü gördün, ve bunları karıştırmak en yaygın bağlantı hatasıdır:

1) Proje endpoint'i (Foundry proje) https://{kaynak}.services.ai.azure.com/api/projects/{proje} → AIProjectClient, agent oluşturma (Eğitim 1-2) için 2) Azure OpenAI uyumlu endpoint https://{kaynak}.openai.azure.com/openai/v1/ → Responses/ChatCompletions/Images/Videos API (Eğitim 1, 3, 4) için 3) Foundry KAYNAK endpoint'i (proje değil!) https://{kaynak}.services.ai.azure.com → Content Understanding, Document Intelligence, Speech, Language gibi Foundry Tools servisleri (Eğitim 3-4) için
Kural of thumb

"Agent oluşturuyorsam" → proje endpoint'i. "Bir OpenAI-uyumlu API çağırıyorsam" (chat, görsel, video) → /openai/v1/ ile biten Azure OpenAI endpoint'i. "Bir Foundry Tools servisi çağırıyorsam" (Content Understanding, Speech, Language, Document Intelligence) → sondaki yol olmadan, sade kaynak endpoint'i.

Responsible AI / Content Safety (Eğitim 1'de detaylı, ama her modülde arka planda var)

4 katmanlı savunma modeli (defense in depth): Model (doğru modeli seç) → Safety System (Azure AI Content Safety filtreleri) → Metaprompt & grounding (system message + RAG) → User experience (arayüz uyarıları). Görsel/video üretim modelleri (Eğitim 4) ve konuşma modelleri (Eğitim 3) için de aynı mantık geçerli — ör. Sora 2'nin gerçek insan yüzü/telifli karakter kısıtlamaları bu katmanın bir parçası.

Genel eğilim

Microsoft'un resmi kurs alıştırmaları giderek Entra ID (keyless) yöntemine kayıyor — az login yapıp DefaultAzureCredential() kullanmak, API key'i koda/​.env'e gömmekten daha güvenli kabul ediliyor. Ama Speech SDK gibi daha "klasik" servisler hâlâ key+region ikilisini yaygın şekilde kullanıyor. Production'a geçerken, mümkün olduğunca Entra ID'ye yönelmek önerilir.

Sık yapılan hata

DefaultAzureCredential() kullanan bir script'i çalıştırmadan önce terminalde az login yapmayı unutmak — en sık karşılaşılan "401 Unauthorized" hatasının sebebi budur. İkinci en sık hata: yanlış endpoint türünü kullanmak (yukarıdaki "Endpoint karmaşası" bölümüne bak).

Servisler Arası Bağlantılar

Aynı servis, farklı eğitimde farklı yüz4 eğitim ayrı ayrı işlenmiş olsa da, bazı servisler birden fazla eğitimde tekrar tekrar karşına çıkıyor — bu tekrarları fark etmek büyük resmi netleştirir.

Azure AI Search ↔ Foundry IQ

Eğitim 4, Modül 8'de Azure AI Search'ü ham haliyle (indexer/skillset/knowledge store) görüyorsun. Eğitim 2, Modül 4'teki Foundry IQ, Microsoft'un kendi ifadesiyle "Azure AI Search'ün evrimi" — yani aynı motorun, agent'lara özel, kurumsal/paylaşımlı bilgi tabanı hâline getirilmiş üst katmanı. Birini anlarsan diğeri çok daha kolay oturur.

MCP (Model Context Protocol)

Eğitim 2, Modül 3'te genel MCP mimarisini (server barındırır, client list_tools() ile keşfeder) öğrendin. Eğitim 3, Modül 2 ve 5'te bunun Language ve Speech'e özel uygulamalarını gördün. Mantık her seferinde aynı: server araç sunar, agent hangi aracı çağıracağına prompt'a göre kendi karar verir.

Content Understanding ↔ Document Intelligence

İkisi de "belgeden/içerikten yapılandırılmış veri çıkar" problemini çözüyor ama farklı nesillerden: Document Intelligence (Eğitim 4, Modül 7) daha eski, belge-odaklı, OCR+deep learning tabanlı. Content Understanding (Eğitim 4, Modül 4-6) daha yeni, generative AI tabanlı ve belge dışında resim/ses/video'yu da kapsıyor. Yeni projelerde Content Understanding'in kapsamı daha geniş, ama Document Intelligence hâlâ belge-özel senaryolarda (özellikle custom model eğitimi) tercih ediliyor.

Responses API her yerde

Eğitim 1'de öğrendiğin Responses API deseni (client.responses.create(), input_text/input_image content tipleri, previous_response_id ile state) Eğitim 4'ün Modül 1'inde (vision chat) neredeyse birebir aynı şekilde tekrar karşına çıkıyor — sadece içeriğe görsel eklendi.

Foundry Agent Service ↔ Agent Framework

Eğitim 2'nin ilk 6 modülü azure-ai-projects ile portalda kalıcı agent'lar kurmayı öğretiyor; Modül 7-8 ise agent-framework ile uygulama içi (in-process), kodla yönetilen agent'lara geçiyor. İkisi rakip değil — aynı Foundry projesine farklı iki kapıdan giriyorsun.
