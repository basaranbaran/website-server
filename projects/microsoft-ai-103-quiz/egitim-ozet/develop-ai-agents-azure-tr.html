Modül 01 / 09

Develop AI agents with Microsoft Foundry and Visual Studio CodeAI agent nedir, Foundry Agent Service ne sağlar, ilk agent'ını portalda ve VS Code'da kur.

Bu modül aslında ne anlatıyor?

Önceki kursta bir modele mesaj gönderip cevap alıyordun — konuşma geçmişini sen elle tutuyordun (messages.append(...) hatırlıyor musun?). Bu modülün temel iddiası şu: Foundry Agent Service, bu "elle yönetim" işinin çoğunu senin yerine yapan bir yönetilen (managed) hizmettir.

1. AI Agent nedir?

Bir agent, bir dil modelinin üzerine üç şey ekler:

InstructionsAgent'ın rolünü ve davranışını tanımlayan kalıcı talimat (system message'ın kalıcı hâli)
ToolsAgent'ın çağırabileceği araçlar (fonksiyon, arama, kod çalıştırma, vb.)
State (Thread)Konuşmanın hafızası — kim ne dedi, hangi araç ne döndürdü

2. Microsoft Foundry Agent Service ne sağlar?

Kendi başına bir agent sistemi kurmaya çalışsan, şunları sen kodlaman gerekirdi: konuşma geçmişini bir veritabanında saklamak, model "şu aracı çağırmalıyım" dediğinde bunu yakalayıp yönetmek, ölçeklenme ve altyapı... Foundry Agent Service bunların hepsini otomatik yönetir.

Zihinde nasıl otursun

Modül 1'in kendi quiz sorusu tam bunu soruyor: "Foundry Agent Service'in standart API'lere göre birincil avantajı nedir?" Cevap: tool calling, state management ve altyapıyı otomatik olarak yönetmesi — daha güçlü model erişimi sağlaması değil, sadece Azure portalında çalışması değil.

3. Geliştirme yaklaşımları (Explore development approaches)

YöntemNe zaman kullanılır
Foundry portal (no-code)Hızlı prototipleme, iş kullanıcılarının denemesi
VS Code + Foundry uzantısıGeliştiricinin IDE içinden agent'ları görüp test etmesi
SDK (Python/C#/JS)Uygulamana entegre, kod ile yönetilen agent'lar

4. Konuşma durumu (state) nasıl yönetilir?

Foundry Agent Service'te konuşma durumu, servis tarafında otomatik olarak yönetilir — sen elle bir mesaj listesi biriktirmezsin, yerel dosyaya da yazmazsın, dış bir veritabanına da bağlanmazsın. Bunun yerine bir thread (konuşma dizisi) oluşturur, mesajları o thread'e eklersin, servis geçmişi otomatik korur.

5. Tool çağırma akışı

Agent bir aracın gerekli olduğuna karar verdiğinde ne olur? Agent aracı otomatik olarak çağırır, sonucu işler ve cevabına dahil eder — kullanıcıdan izin istemez, işlemeyi durdurup geliştiriciyi beklemez, ayrı bir kuyruğa da göndermez (tabii ki insan onayı gerektiren "approval-required" araçlar hariç — bu Modül 8'de detaylanıyor).

💻 Çalışır kod: İlk agent'ını oluştur

Sık karıştırılan noktalar (quiz odaklı)

Foundry Agent Service kullanmanın standart API'lere göre birincil avantajı nedir?
Tool calling, state management (konuşma durumu yönetimi) ve altyapıyı otomatik olarak yönetmesidir. Daha güçlü modellere erişim sağlaması ya da sadece Azure portalında çalışması değil — asıl fark, senin elle yapman gereken "sistem mühendisliği" işini üstlenmesidir.
Foundry Agent Service konuşma durumunu (state) nasıl yönetir?
Servis tarafında otomatik olarak. Geliştiricinin konuşma geçmişini elle yönetmesi, dış bir veritabanına bağlanması veya yerel dosya sistemi kullanması gerekmez — bu, önceki kursun ChatCompletions API'sindeki elle mesaj biriktirme yönteminden temel farkıdır.
AI agent'lar için önerilmeyen güvenlik pratiği hangisidir?
Agent'lara tüm kurumsal veriye sınırsız erişim vermek. Rol tabanlı erişim kontrolleri (RBAC), prompt filtreleme/doğrulama ve kapsamlı loglama/izlenebilirlik — bunların hepsi önerilen pratiklerdir; sınırsız erişim değildir.
Agent bir aracın gerekli olduğuna karar verdiğinde ne olur?
Agent aracı otomatik olarak çağırır, sonuçları işler ve kendi cevabına dahil eder. Kullanıcıdan izin istemez ya da geliştiriciyi beklemez (insan onayı gerektiren özel "approval-required" araçlar dışında — bkz. Modül 8).

Modül 02 / 09

Integrate custom tools into your agentHazır araçlar yetmediğinde: fonksiyon, OpenAPI ve Azure Functions ile agent'ını genişlet.

Bu modül aslında ne anlatıyor?

Foundry'nin hazır araçları var (code_interpreter, file_search, web_search — önceki kursun Modül 4'ünü hatırla). Ama bazen agent'ının senin kendi iş mantığına erişmesi gerekir: şirket veritabanın, dahili bir API, kendi Python fonksiyonun. Bu modül, bunun için 3 farklı yolu karşılaştırıyor.

Custom tool'lar nedir?

Custom tool'lar, agent'ın yeteneklerini genişletmek için çağırabileceği fonksiyonlardır. Dikkat: bunlar VS Code uzantıları değildir, fine-tune edilmiş modeller de değildir — sadece agent'ın ihtiyaç duyduğunda çağırdığı, senin tanımladığın çağrılabilir (callable) kod parçalarıdır.

Üç uygulama seçeneği

SeçenekNe zaman kullanılırÇalıştığı yer
Function toolUygulama kodunda zaten yazılı bir yerel fonksiyon varsaSenin agent uygulaman içinde (in-process)
OpenAPI spec toolEntegre edeceğin şey zaten bir OpenAPI 3.0 web servisiyseDış HTTP servisi, doğrudan çağrılır
Azure Functions toolKurumsal sistemlere, sunucusuz (serverless) ve durumlu (stateful) şekilde bağlanman gerekiyorsaAzure Functions üzerinde, kuyruk tabanlı (queue-based) entegrasyon
Quiz'de doğrudan sorulan iki senaryo

"Bir OpenAPI 3.0 tabanlı web servisini agent'a entegre etmen gerekiyor, ne yaparsın?" → Web servisini Python fonksiyonuna dönüştürüp koda gömmek değil; servisin OpenAPI şemasını agent'ın talimatlarına eklemek de değil — doğru cevap: OpenAPI specification tool olarak agent tanımına eklemek.

"Agent uygulama kodunda zaten yerel bir fonksiyon var, agent'ın bunu çağırmasını istiyorsun" → function tool eklersin (code_interpreter ya da Azure Functions değil).

💻 Çalışır kod: Function tool ekleme

Herhangi bir Python fonksiyonunu, tipini ve docstring'ini agent'ın "araç kataloğuna" eklersin. Model, docstring'i okuyarak fonksiyonu ne zaman çağıracağına karar verir:

function_tool_ornek.py
import os, json
from typing import Set, Callable, Any
from dotenv import load_dotenv
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import FunctionTool, ToolSet, PromptAgentDefinition

load_dotenv()
project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)

# 1) Kendi Python fonksiyonunu tanımla — docstring ZORUNLU, model bunu okur
def fetch_weather(location: str) -> str:
    """
    Belirtilen konum için hava durumu bilgisini getirir.
    :param location (str): Hava durumu istenen konum.
    :return: Hava durumu bilgisi, JSON string olarak.
    :rtype: str
    """
    mock_data = {"İstanbul": "Parçalı bulutlu, 24°C", "Ankara": "Güneşli, 27°C"}
    weather = mock_data.get(location, "Bu konum için veri yok.")
    return json.dumps({"weather": weather})

# 2) Fonksiyonu bir ToolSet içine ekle
user_functions: Set[Callable[..., Any]] = {fetch_weather}
functions = FunctionTool(user_functions)
toolset = ToolSet()
toolset.add(functions)

# 3) Toolset'i agent tanımına ekle
agent = project.agents.create_version(
    agent_name="HavaAsistani",
    definition=PromptAgentDefinition(
        model=os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"],
        instructions="Sen hava durumu sorularını fetch_weather aracını kullanarak cevaplayan bir asistansın.",
        tools=toolset.definitions,
    ),
)
print(f"Tool'lu agent oluşturuldu: {agent.name}")

Model yine fonksiyonu kendisi çalıştırmaz — "bu fonksiyonu şu parametrelerle çağır" der, sonucu senin kodun üretir ve modele geri gönderir. Foundry Agent Service bu geri-gönderme akışının çoğunu otomatikleştirir, ama mantık aynıdır.

Modül 03 / 09

Integrate MCP Tools with Azure AI AgentsModel Context Protocol ile agent'ına dinamik, keşfedilebilir araç erişimi kazandır.

Bu modül aslında ne anlatıyor?

MCP (Model Context Protocol), modellere araç sağlamanın açık bir standardıdır. Modül 2'deki custom tool'larla farkı şu: MCP'de araçları tek tek koda gömmezsin — bir MCP sunucusuna bağlanırsın, sunucu hangi araçları sunduğunu söyler (discovery), sen de bunları dinamik olarak kullanırsın.

MCP mimarisi: sunucu ve istemci

MCP serverAraç tanımlarını barındırır ve istemciler tarafından keşfedilmesini (discovery) sağlar
MCP clientSunucudaki araç kataloğunu session.list_tools() ile çeker
Sık karışan nokta

MCP server, agent'ı doğrudan çalıştırmaz ve kullanıcı prompt'larını işlemez — sadece araç tanımlarını sunar. Ajanların arasındaki ağ bağlantısını da yönetmez. Tek işi: "işte kullanabileceğin araçlar" demektir.

Neden async fonksiyonlarla sarmalanır?

MCP araçları, istemci tarafında async (asenkron) fonksiyonlarla sarmalanır — bunun sebebi kullanıcı girdisini beklemek ya da fonksiyonları otomatik REST endpoint'lerine çevirmek değil, agent'ın araç çağrısı sırasında bloklanmadan (non-blocking) diğer işlemlere devam edebilmesini sağlamaktır.

💻 Çalışır kod: Agent'a MCP aracı bağlama

Microsoft Agent Framework, 3 farklı MCP bağlantı tipi sunar. En basiti, yerel (stdio) bir MCP sunucusuna bağlanmak:

mcp_local_ornek.py
import asyncio
from agent_framework import Agent, MCPStdioTool
from agent_framework.openai import OpenAIChatClient

async def main():
    # MCP sunucusunu yerel bir alt-süreç (stdio) olarak başlat ve bağlan
    async with (
        MCPStdioTool(
            name="calculator",
            command="uvx",
            args=["mcp-server-calculator"],
        ) as mcp_server,
        Agent(
            client=OpenAIChatClient(),
            name="MatematikAsistani",
            instructions="Sen hesaplama yapan yardımsever bir matematik asistanısın.",
        ) as agent,
    ):
        # Agent'a bu çalışmada MCP sunucusundaki tüm araçları kullanma izni ver
        result = await agent.run("15 çarpı 23 artı 45 kaçtır?", tools=mcp_server)
        print(result)

if __name__ == "__main__":
    asyncio.run(main())

Çalıştırmak için: pip install "mcp[cli]" --pre sonra python mcp_local_ornek.py

Uzak (HTTP tabanlı) bir MCP sunucusuna Foundry üzerinden bağlanmak da benzer mantıkla çalışır:

mcp_http_ornek.py
import asyncio, os
from dotenv import load_dotenv
from agent_framework import Agent, MCPStreamableHTTPTool
from agent_framework.foundry import FoundryChatClient
from azure.identity.aio import AzureCliCredential

load_dotenv()

async def main():
    async with AzureCliCredential() as credential:
        client = FoundryChatClient(
            project_endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
            model=os.environ["FOUNDRY_MODEL"],
            credential=credential,
        )
        async with (
            MCPStreamableHTTPTool(
                name="Microsoft Learn MCP",
                url="https://learn.microsoft.com/api/mcp",
            ) as mcp_server,
            Agent(
                client=client,
                name="DokumanAsistani",
                instructions="Microsoft dokümantasyonu ile ilgili sorulara yardımcı olursun.",
            ) as agent,
        ):
            # 2) MCP client, sunucudaki araçları otomatik keşfeder (session.list_tools() mantığı)
            result = await agent.run(
                "Azure CLI ile bir storage account nasıl oluşturulur?",
                tools=mcp_server,
            )
            print(result)

if __name__ == "__main__":
    asyncio.run(main())

import asyncio
from agent_framework import ChatAgent
from agent_framework.azure import AzureAIAgentClient
from azure.identity.aio import AzureCliCredential

async def main():
    async with AzureCliCredential() as credential:
        # 1) AzureAIAgentClient: Foundry projene bağlanan istemci
        #    (ortam değişkenlerinden okur: AZURE_AI_PROJECT_ENDPOINT, AZURE_AI_MODEL_DEPLOYMENT_NAME)
        client = AzureAIAgentClient(async_credential=credential)

        # 2) ChatAgent: talimatlar ve (opsiyonel) araçlarla tanımlanan agent
        agent = ChatAgent(
            chat_client=client,
            name="TurizmAsistani",
            instructions="Sen İstanbul'u ziyaret eden turistlere kısa, net cevaplar veren bir rehbersin.",
        )

        # 3) AgentThread: konuşma durumunu yöneten nesne
        thread = agent.get_new_thread()

        # Aynı thread'i kullanarak çok adımlı bir konuşma yürüt
        cevap1 = await agent.run("Sultanahmet'e nasıl giderim?", thread=thread)
        print("Asistan:", cevap1.text)

        cevap2 = await agent.run("Oradan Kapalıçarşı'ya yürüyerek gidilir mi?", thread=thread)
        print("Asistan:", cevap2.text)   # thread sayesinde önceki bağlamı hatırlar

if __name__ == "__main__":
    asyncio.run(main())

Agent'a özel fonksiyon (custom) ekleme

Custom fonksiyonellik eklemenin doğru yolu: tip anotasyonlu (type-annotated) ve açıklamalı Python fonksiyonları yazıp bunları ChatAgent'ın tools parametresine geçirmek — Azure portalında bağlantı string'i ile fonksiyon bağlamak ya da modelin mimarisini değiştirmek değil.

agent_ile_tool.py
import asyncio
from typing import Annotated
from pydantic import Field
from agent_framework import ChatAgent
from agent_framework.azure import AzureAIAgentClient
from azure.identity.aio import AzureCliCredential

# Tip anotasyonlu, açıklamalı fonksiyon — model bu bilgiyi okuyarak
# fonksiyonu ne zaman/nasıl çağıracağına karar verir
def get_weather(
    location: Annotated[str, Field(description="Hava durumu istenen şehir")]
) -> str:
    """Belirtilen şehir için hava durumunu döner."""
    return f"{location} için hava: parçalı bulutlu, 22°C."

async def main():
    async with AzureCliCredential() as credential:
        client = AzureAIAgentClient(async_credential=credential)
        agent = ChatAgent(
            chat_client=client,
            name="HavaAsistani",
            instructions="Hava durumu sorularını get_weather aracıyla cevaplarsın.",
            tools=[get_weather],   # NOT: fonksiyonu doğrudan tools parametresine ver
        )
        thread = agent.get_new_thread()
        result = await agent.run("İzmir'de hava nasıl?", thread=thread)
        print(result.text)

if __name__ == "__main__":

from agent_framework import Agent
from agent_framework.orchestrations import GroupChatBuilder, GroupChatState

arastirmaci = Agent(client=chat_client, name="Arastirmaci",
    instructions="Kısa, faktüel notlar topla.")
yazar = Agent(client=chat_client, name="Yazar",
    instructions="Toplanan notları kullanarak net, yapılandırılmış cevap yaz.")

def round_robin_secici(state: GroupChatState) -> str:
    isimler = list(state.participants.keys())
    return isimler[state.current_round % len(isimler)]

workflow = GroupChatBuilder(
    participants=[arastirmaci, yazar],
    termination_condition=lambda conversation: len(conversation) >= 4,
    selection_func=round_robin_secici,
).build()

stream = workflow.run("Python'da async/await'in temel faydaları nelerdir?", stream=True)
async for event in stream:
    if event.type in ("intermediate", "output"):
        print(f"[{event.executor_id}]", event.data)

handoff_ornek.py
from agent_framework.orchestrations import HandoffBuilder

triaj = chat_client.as_agent(
    instructions="Müşteri sorununu doğru uzman agent'a yönlendir.",
    name="triaj_agent",
)
iade_agent = chat_client.as_agent(

    name="iade_agent",
)

    instructions="Kargo/teslimat sorularını çözersin.",
    name="kargo_agent",
)

workflow = (
    HandoffBuilder(
        name="musteri_destek",
        participants=[triaj, iade_agent, kargo_agent],
    )
    .with_start_agent(triaj)   # İlk mesajı triaj_agent karşılar

# Handoff etkileşimlidir: bir agent devretmeden cevap verirse, workflow

Agent Skill nedir?

Bir skill, bir yetenektir — agent'ın diğer agent'lara/istemcilere "şu işi yapabilirim" demesinin yoludur. Her skill'in alanları: id (benzersiz kimlik), name (okunabilir etiket), description (ne yaptığı), tags (keşif için anahtar kelimeler), examples (örnek promptlar) ve input/output modes (desteklenen veri formatları).

agent_executor.py
from a2a.server.agent_execution import AgentExecutor, RequestContext
from a2a.server.events import EventQueue
from a2a.server.tasks import TaskUpdater
from a2a.utils import new_agent_text_message

class SelamAgentExecutor(AgentExecutor):
    """A2A protokolü ile agent mantığın arasındaki köprü."""

    async def execute(self, context: RequestContext, event_queue: EventQueue) -> None:
        # Gelen kullanıcı mesajını al
        kullanici_metni = context.message.parts[0].root.text

        # Kendi agent mantığın burada çalışır (basitlik için sabit cevap;
        # gerçek projede burada bir ChatAgent.run() çağrısı olurdu)
        cevap = f"Merhaba! Şunu aldım: '{kullanici_metni}'"

        await event_queue.enqueue_event(new_agent_text_message(cevap))

    async def cancel(self, context: RequestContext, event_queue: EventQueue) -> None:
        # Devam eden bir görevi iptal etme mantığı (bu örnekte gerekmiyor)
        raise NotImplementedError("Bu agent iptal etmeyi desteklemiyor.")

    tags=["selamlama", "ornek"],
    examples=["merhaba", "nasılsın"],

    output_modes=["text/plain"],
)

agent_card = AgentCard(

    description="Basit bir karşılama agent'ı",
    url="http://localhost:9999/",
    version="1.0.0",

💻 Çalışır kod: Uzak bir A2A agent'ına bağlanma (client)

Bir istemci, önce agent'ın kartını "keşfeder" (discovery), sonra ona mesaj gönderir:

client.py
import asyncio
from uuid import uuid4
import httpx
from a2a.client import A2ACardResolver, A2AClient
from a2a.types import MessageSendParams, SendMessageRequest

async def main():
    base_url = "http://localhost:9999"
    async with httpx.AsyncClient() as httpx_client:
        # 1) Agent Card'ı keşfet (discovery)
        resolver = A2ACardResolver(httpx_client=httpx_client, base_url=base_url)
        agent_card = await resolver.get_agent_card()
        print(f"Keşfedilen agent: {agent_card.name} — {agent_card.description}")

        # 2) A2AClient oluştur ve mesaj gönder
        client = A2AClient(httpx_client=httpx_client, agent_card=agent_card)
        payload = {
            "message": {
                "role": "user",
                "parts": [{"kind": "text", "text": "Merhaba, nasılsın?"}],
                "messageId": uuid4().hex,
            }
        }
        request = SendMessageRequest(id=str(uuid4()), params=MessageSendParams(**payload))
        response = await client.send_message(request)
        print(response.model_dump(mode="json", exclude_none=True))

if __name__ == "__main__":
    asyncio.run(main())
